## 起動・比較

1. 本番アプリの `index.html` をLive Serverで開く。
2. URL末尾の `index.html` を `diagnostics/tied-fret-lab.html` に置き換える。
   アプリフォルダがサーバーのルートなら `http://127.0.0.1:5500/diagnostics/tied-fret-lab.html`。
3. 「ソロギター EX03」「スケール1.0」「1 SVGあたり10小節」を選ぶ。
4. A → B → Cを切り替え、同じ小節を比較する。切替は毎回新しいモデルとSVGを生成する。
5. 縦型カードの前後ボタンで第1〜8小節を見る。拡大図も選択小節へ追従する。
6. 「解析結果」で追加件数と見送り理由を確認できる。「結果をコピー」でJSONを取得する。
7. 複数SVGは「2小節」、倍率は0.8/1.0/1.25で比較できる。画面サイズ変更・再描画も同じ検証をやり直す。

音声再生・練習ボタンはありません。追加のAudioContextは作りません。
CDNに接続できない場合はalphaTabを読み込めません。

## A / B / C

| 条件 | 内容 | EX03・スケール1.0 |
|---|---|---|
| A | alphaTab標準の元SVGを変更しない | 低音の括弧数字4音、上声の終点8音は省略 |
| B | 省略数字だけ追加。失敗例の観察用で採用不可 | 上声8音に数字を追加するが、弦・符尾・タイが数字を貫く |
| C | 数字と、対象の弦・符尾・タイ終端を整合させる | 上声8音すべて追加。低音4音は変更しない |

数字の実フォントは標準と同じ14px Arial, sans-serif、黒。小音符の数字は11px。
フォントや大きさを推測せず、alphaTabのRenderingResourcesを利用する。
数字・括弧の幅は実際に生成したSVG textのbboxで測り、固定幅にはしない。
2桁フレットはモデル識別の専用テスト済み。ただし今回のEX03に2桁がないため、実譜面での完成した2桁表示は未検証。

## 音符・曲線の識別

- `note.id` と原モデルの `tieOrigin` / `tieDestination` の相互参照を照合する。
- part相当のtrack、staff、voice、小節、beat順序が整合する同一小節内の通常タイを対象とする。
- NoteBoundsをnoteオブジェクトとIDで一意に照合する。幅・高さが正で標準数字がある音は除外する。
- 対象は幅・高さとも0の省略数字。座標取得失敗、重複ID、小音符、ベンド、ghost、移調、通常スラーとの併用、タイ連鎖などは見送る。
- モデルで確定した始点・終点のNoteBoundsから、1.8.4標準の閉じた2本の三次曲線の両端を照合する。
- 両端・方向・形状が一致するpathがちょうど1本の場合だけ変更する。単なる「同じ数字」や「近い曲線」は使わない。
- 原本のMusicXMLに座標や文字は書き込まず、タイフラグ・音価・弦・フレットも変更しない。

## Cの描画方法

白い矩形によるマスクは使用しない。

1. 追加する括弧付き数字の実bboxを取得する。
2. bbox外側に0.65 SVG px ×描画scaleの空白範囲を確保する。
3. その位置を通る対象弦の水平rectを一意に確認し、数字の左右の線片へ分割する。
4. 単音beatで、その終点から伸びるリズム符尾を一意に確認できる場合だけ、数字の下端より下の線片を残す。
5. 対応する標準タイの始点・X位置・塗りつぶし輪郭を保ち、終点Yを数字bboxの上（または下）へ合わせる。余白は1 SVG px ×scale。
6. 両側の三次曲線の制御点を同じ比率で追従させる。別の曲線を追加して二重表示にはしない。
7. 数字・周辺曲線・記号への衝突を評価する。曲線はbboxだけでなく、誤差を制限して平坦化した塗りつぶし輪郭で評価する。
8. 元SVGの寸法、小節のX範囲、既存カードのviewBoxとclipPathに収まる場合だけ確定する。

対象の原rectは一時的にdisplay:none、対象pathはdだけを変更し、補助グループに残す線片と数字を配置する。
原属性をWeakMapの復元記録に保存し、同じSVGに再適用する際は先に完全復元する。
対象外の文字・曲線・通常数字は変更しない。変換付きSVG要素や曖昧な曲線は処理しない。

## 複数SVG・縦型・世代管理

- partialLayoutFinishedのIDと、alphaTabが出力したSVG親のrenderedResultIdを照合する。
- BoundsLookupの全体座標からpartialのx/yを差し引き、各SVGの座標へ変換する。
- 先に無補正SVGから本番と同じVerticalTabControllerでカードを生成し、X境界とcropを確定する。
- 曲線と線片の元属性が一意に一致するカード側の要素だけを対応付け、同じ補助表示を複製する。
- 補助表示によって元SVGのwidth/height/viewBox、カードviewBox/clipPathが変わっていないことを実行時にも検証する。
- 条件変更・回転・再描画はAPIとカードを破棄して再構築する。非同期の描画完了はAPIと世代の一致を検証する。
- 拡大図のviewBoxは比較専用であり、元SVGやカードには反映しない。

## 実測結果と制限

- EX03：60note、12タイ終点。標準数字4音と省略対象8音を区別。
- 標準scale1.0：Cは8/8。390×844、844×390、PC1280×900で8/8。
- scale1.25：8/8。元の寸法とcropを維持。
- scale0.8：7/8。第8小節は既存カードcropが `1511.2 25.6 14.2 114.4` となり、数字を入れられないため見送り。
  これは補助表示前からのcrop値。既存verticalTab.jsの修正や、表示範囲の拡張はしていない。
- 2小節/partialの4つの音楽SVG：8/8、縦型8カードで表示。標準のヘッダー/フッターSVGは音楽partialに含めない。
- 同一SVGへ2回再適用しても8音のまま。Aへ戻すと原線片・原タイへ復元。
- タイpathを意図的に重複させたDOM試験では該当1音を見送り、重複を取り除くと8/8へ復帰。
- 原文字（低音の既存括弧数字を含む）は属性単位で同一。変更するpathは照合済みの8本だけ。
- 同じモデルから生成したMIDIイベントはA/Cで同一。60noteに対し発音は48件のまま。
- AudioContextの生成0、ブラウザの未処理例外0。
- 参考test2/test3/test5の和音タイは、別の曲線・数字・符尾への衝突を検知して全候補を見送り。
  小音符モデルとH/P/Sを含む元textはA/Cで同一。通常タイの一般解が完成したわけではない。
- 参考譜面の比較はalphaTabの標準出力が基準。本番の小音符スラー・旗などの独自補正をラボへコピーしていない。
- 実機Fire/AQUOS、Safari/WebKit、ブラウザの90%/110%ズーム、和音・多声部・タイ連鎖の完成表示は未検証。
