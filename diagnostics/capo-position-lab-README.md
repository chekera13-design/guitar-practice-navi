# カポ表記の位置調整・独立ラボ

2026-10-25。alphaTab 1.8.4 build 34、commit `022a45c8e42370f9e12e68949d11eada370da83d` 固定。

通常入口、既存ラボ、スクロール診断、本番コード、楽譜は変更しません。
`staff.capo` は設定しません。表示上の `Capo 2` は移調・音声再生を意味しません。

## 開く手順

1. アプリの `index.html` をLive Serverで開く。
2. URL末尾の `index.html` を `diagnostics/capo-position-lab.html` に置き換える。
   アプリフォルダがサーバールートなら `http://127.0.0.1:5500/diagnostics/capo-position-lab.html`。
3. 「ソロギター EX03・MXL原本」「1.0」「10小節」を基準にA/B/Cを切り替える。
4. 横型、縦型第1小節、先頭拡大図を比較する。縦型の次ボタンで第2小節以降に表示がないことも確認する。
5. 「0.8」「2小節/ SVG」で縮小・複数SVGも比較できる。
6. 別番号・重複・矛盾・一般注釈は、ラボ内で新規生成する仮想入力。既存MusicXML/MXLを編集しない。
7. 「解析結果」でbbox・適用数・見送り理由を読み、「結果をコピー」でJSONを取得できる。

CDN接続が必要。ファイルを直接ダブルクリックせずHTTPで開く。
公開devへの反映・正式公開はしていない。

## 比較条件

| 条件 | 動作 | EX03での結果 |
|---|---|---|
| A | alphaTabの元SVG文字を変更しない | capo2が第1beat・Em付近 |
| B | 左上の既存余白へ移動、Capo Nに統一。周辺記号の衝突判定を省略 | Capo 2がTAB左上 |
| C | 横型・カードの実領域と周辺要素を評価。空間がなければ元表示を維持 | Capo 2がTAB左上。Bと同じ位置で安全を確認 |

B/Cの見た目がEX03では一致するのは、最初の配置候補で衝突がないため。
Cだけに、衝突時の候補探索と見送り判定がある。
元のGeorgia斜体12pxを保持し、元文字を移動・整形する。独自文字を重ねて増やさない。

## 対象文字の識別

- 完全一致の `capo1` / `capo2` / `Capo 2` / `CAPO 3` / `capo 5` 等を認識する。
- 前後空白と英字大小は許容。数字は1〜24。一般文章、複合文、ローマ数字、範囲外は推測しない。
- 原本XMLを読み、part / staff / voice / 小節 / direction順序 / 小節内時刻 / 後続beat・音符列を保持する。
- 最初の小節・最初のbeatに一意に対応する注釈だけを対象とする。
- 対応するモデルのbeat.text、beat.idの一意性、弦・フレット、BeatBoundsのbeat参照とonNotesXを照合する。
- SVGは、そのモデル・partialに対応し、元文字内容と文字アンカーXが一致する単独textを一意に確認する。
- 同じ文字列だけを使ったSVG全体の置換はしない。
- 重複・矛盾・曖昧な声部・途中小節・別トラック・構造化されたstaff.capoがあるケースは見送る。
- 原本にカポ注釈がなければSVGを変更しない。

## 配置基準と安全判定

1. 元のSVGから既存VerticalTabControllerでカードを生成し、cropを先に確定する。
2. 第1小節のMasterBarBounds左端とBeatBounds.onNotesXから左上領域のX範囲を求める。
3. 実際のTAB弦ラインとNoteBoundsの弦位置を照合して、領域の下端を決める。
4. 上端は元SVGと第1カードcropの両方へ収まる位置とする。文字を無条件に上へ動かさない。
5. 余白はfont-sizeの0.18倍、周辺要素との間隔は0.15倍、候補間隔は0.25倍。EX03用の固定座標はない。
6. 正規化後の文字はSVG textを一時測定し、実bboxの大きさで配置する。
7. Cは横型・第1カード両方のコード名、TAB、拍子、数字、線・曲線等との衝突を評価する。
8. nominal候補が衝突するときだけ、同じ左上領域内で右・下へ候補探索する。入らなければ元表示へ戻す。
9. 確定後に実bboxを再取得し、crop内・衝突なしを再確認する。失敗時は全て復元する。

### 音楽フォントのbboxについて

実測では、TAB・拍子のSVG text bboxは高さ144などのフォント全体の余白を含み、実字形より大幅に大きい。
これをそのまま占有領域にすると、空いている左上領域まで衝突扱いになる。

通常要素はSVG実bboxを使用し、座標変換は公開のCTMを用いて元SVG座標へ合わせる。
単純なalphabetic配置のSMuFL文字だけは、Canvasの実インク境界をSVGの文字advanceと照合し、補足の字形領域として使う。
Canvas/SVG双方の丸め分をCSSピクセル換算で外側へ加えて保守的に評価する。
フォント・advance・座標変換を確認できない場合は、元の大きいbboxへ戻す。衝突判定は無効化しない。

## 複数SVG・縦型・再描画

- partialのIDとSVG親のrenderedResultIdを照合し、全体の第1小節を含む音楽partialだけを対象とする。
- BoundsLookupの全体座標からpartial.x/yを差し引く。フッター等のSVGは対象外。
- 元注釈の属性・文字が一致するカード複製を照合し、第1小節の文字だけを移動する。
- 第2小節以降の既知の複製は取り除く。復元用placeholderで元位置を保持し、Aへ戻す際は復元できる。
- 同じSVGへの再適用は原属性・原文字・原複製を復元してから行うので、文字は増えない。
- 画面サイズ・条件・譜面変更と再描画は、新しいAPIとSVGで再照合する。API・score・世代の不一致を適用しない。
- 元SVGのwidth/height/viewBox、カードのviewBox/clipPath、小節幅を変更しない。
- 字幕はSVGの一部なので横スクロールに追従する。補助処理の前後でscrollLeftとscrollWidthが変わらないことも確認した。
- 拡大図は比較用の複製であり、そこでの切り抜きを元SVGへ反映しない。

## 確認結果

- EX03：原本注釈1件を識別。B/Cとも1件移動、低音・通常タイ・コード記号・他の注釈は変更なし。
- 標準scale1.0の例：元文字bbox左上 `(108.00,32.80)` から、正規化後 `(37.16,34.96)` へ移動。
  これらは実測結果であり、コード内の固定値ではない。
- 縦型第1カードでもCapo 2がcrop内。第2〜8カードには補助文字を出さない。
- PC1280×900、390×844、844×390、回転、再描画、4つの音楽partialで成功。
- scale0.8でも第1小節のカポ文字は安全に表示できた。
  ただし既知の第8小節cropが狭くなる問題はそのまま。カポ表示改善が全カードのcrop問題を解決したとは扱わない。
- カポなしEX01：認識0・移動0。
- 新規仮想入力のcapo1 / Capo 2 / CAPO 3 / capo 5：各1件移動しCapo Nに統一。
- 重複と矛盾：いずれも原本2候補を検知し、元表示維持。
- 一般注釈：認識0・変更なし。
- 同一SVGへ2回適用しても元SVG1件・第1カード1件のまま。Aで同じSVGの元注釈へ復元。
- 左上全体を塞ぐ一時DOM障害物の試験ではCを見送り、取り除くと復帰した。
- staff.capo=0、チューニング、pitch、string/fret、音価、タイ、beat.text、コード名は維持。
- EX03のMIDI発音イベントはA/Cで全内容同一、48件のまま。
- AudioContext生成0、ブラウザ未処理例外0。

## 本番採用の評価・残る課題

Cは、EX03および指定された仮想ケースの範囲で本番統合候補にできる。
ただし本番統合はしていない。利用者が比較画像で位置・書体・読みやすさを確認してから判断する。

未検証：Fire/AQUOS実機、Safari/WebKit、ブラウザの90%等のズーム、複雑な多段・複数トラック。
途中でカポが変わる譜面、構造化capoと文字注釈の併用は対象外で、推測して移動しない。
未知のフォントや座標系ではCの安全判定が見送る可能性がある。

将来の統合には表示専用モジュールとapp.jsの原本保持・描画完了・カード複製・世代管理への接続が必要。
既存のcrop内へ収まる今回の範囲では、verticalTab.jsや音声処理の変更は不要と考えられる。
